# Sweep 优化验证记录

目标：降低已打开 Sweep 的监控开销，修正指标和文件大小统计，保持五模块结构。

## 修改前证据

- 原路径：`/Users/focus/Sweep`；工作副本保留原文件哈希与 original-sources。
- 15 秒进程 CPU 时间差：46.85% 单核 CPU；627 个进程。完整值见 baseline-performance.json。
- H1 已确认：CPU_STATE_MAX 为 4，原步长却为 6；10 核返回 40 个计数，原 guard 恒失败。
- H2 已确认：getifaddrs 的 AF_LINK ifa_data 为 if_data（96 字节），原按 if_data64（128 字节）读取。
- H3 已确认：ps pmem 换算漏乘 10，且一位小数精度不足；改以 RSS KiB 统计。
- H4 已确认：文件根目录枚举返回 0；嵌套 Fake.app 中 8192 字节被 skipsPackageDescendants 漏计。
- H5 已确认：缓存目录存在重复标准化路径，重复扫描并重复累加。
- H6 已验证改善：进程表按需渲染、后台合并采样并去除每秒重启的仪表补间动画后，CPU 时间差占用由 46.85% 降至 2.90%。原版调用栈主要为全量布局，首个 UI 版本仍有刷新动画开销；各项贡献未单独隔离。

验收：回归测试先失败后通过，release 编译与签名检查，启动真实 app 核对 CPU/RSS/网络，排序、置顶和页面切换，记录修后 CPU。验证过程只读用户数据。

## 当前验证

- 原版文件体积夹具：4/7 通过，普通文件、sizeIfPresent、嵌套应用三项失败（size-regression-before.txt）。
- 修后独立回归：32/32 通过（regression-after.txt），涵盖文件、包、硬/软链接、CPU 差分/回绕、网络回绕/重连、RSS、缓存去重和采样启停。
- Release 编译、app 签名与 Info.plist 验证通过，版本 0.1.1。
- 新采样逻辑只读实机核对：CPU 23.58%，下行 183605 B/s，上行 35846 B/s，磁盘空闲 19637059584 字节，物理内存 16 GiB，665 个进程（live-system-readings.json）。各次采样为不同时刻，不作性能对照。
- 二次复核发现已取消视图任务重启独立采样的窄竞态，已加入 Task.isCancelled 检查；重启时清空历史，避免将暂停前的点当作连续一分钟。
- 用户手动解锁后，已重启最终安装版本，PID 50458。监控页、实时 CPU / 网络、16 GB 内存总量、RSS 以及整体布局均已实机查看。
- CPU / 内存 / 名称排序、置顶与取消置顶、监控和优化页连续十轮切换通过；未点击任何维护执行按钮（ui-validation.json）。
- 最终界面隐藏分段选择器重复标题，CPU / 内存 / 磁盘颜色统一按 80% / 90% 占用率分级，避免普通占用显示红色。

## 已发现但未扩大本轮范围的问题

- 原版 PathSafety.isProtected 对根目录的前缀判断会匹配所有绝对路径，Remover 路径可能全部被跳过。
- 原版 Analyze / Uninstall 失败时调用管理员永久删除，和“移入废纸篓、可恢复”的文案矛盾；卸载结果还会忽略失败并宣称全部成功。
- 本轮保留上述原有操作策略，未执行用户文件清理、卸载、一键维护或管理员删除。后续修复需单独设计可恢复路径与真实结果报告。
- Sizer 表示逻辑体积，同一树内硬链接去重；多个条目各自统计时共享的硬链接、APFS 克隆、稀疏文件不等于实际释放量。

## 性能对照与限制

- 旧版：15.00 秒窗口，CPU 46.85%，进程数 627；末次 RSS 125.0 MiB。
- 最终版：15.18 秒窗口，CPU 2.90%，进程数 625；末次 RSS 147.9 MiB。
- 本次 CPU 对照下降约 93.8%。窗口均为监控页、CPU 排序、无置顶、顶部位置；测量期间无 UI 操作。CPU 为进程 CPU 时间除以实际时长的单核口径。
- 首个 UI 版本实测 20.01%，最终去除实时仪表补间动画后再测 2.90%；两轮负载与运行时长不同，不能将差额全部归因于动画。
- 采样时间、其他软件负载及缓存状态不同，这是本机短时对照，不代表所有机器、峰值或长时间内存稳定性。RSS 本次高于旧版，未宣称内存占用下降。
- 完整数据：baseline-performance.json、after-performance.json、final-performance.json；最终汇总：build-result.json。
